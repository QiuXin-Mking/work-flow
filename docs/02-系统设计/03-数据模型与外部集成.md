# 数据模型与外部集成

## 1. 数据对象与版本

状态数据库为 /data/jobs.sqlite，API 和 Worker 共用持久卷。SQLite 启用 WAL；门槛变更、任务领取和重试使用事务。字段之间的关联由应用校验维护。

| 表 | 主键或关联 | 内容 |
| --- | --- | --- |
| users | id / username | 本地身份、scrypt 密码哈希、active |
| sessions | token_hash / user_id | 会话 token 的 SHA-256 哈希、有效期 |
| jobs | id / created_by / candidate_id | 工单 URL、分析仓库集合、原始 snapshot_json、任务状态、错误、租约与时间 |
| job_snapshots | job_id + version | 独立快照版本、内容与保存时间 |
| job_workflows | job_id | data_json 保存阶段、版本、报告、用户确认与 PRD 审查 |
| attempts | id / job_id / epoch | 执行次数、租约代次、状态和开始时间 |
| events | id / job_id | 事件类型、payload、epoch 和时间 |
| candidates | id / job_id / attempt_id | 逐仓候选、修前复现与修后验证标记 |
| approvals | candidate_id / reviewer_id | 审核身份与冻结候选绑定 |
| deliveries | candidate_id | 逐仓 PR、交付状态与时间 |

快照是输入证据，不是 PRD。原始飞书输入与用户补充分开记录。snapshot_version 指向当前输入快照，source_snapshot_version 指向原始工单来源版本；revision 是整个工作流的乐观锁版本。修改补充、刷新源工单、阶段结果或用户决策推进 revision，不能用过期 revision 覆盖新结果。

来源：[Store](../../backend/app/store.py)、[WorkflowStore](../../backend/app/workflow.py)。

## 2. 工作流 DTO

任务详情中 workflow 对象包含以下字段：

| 字段 | 语义 |
| --- | --- |
| stage | information、root_cause、business_confirmation、prd、prd_review、implementation |
| revision | 用户写操作必须携带的 expectedRevision |
| snapshot_version / source_snapshot_version / snapshot_hash | 输入与源版本及内容绑定 |
| input | 使用者确认的故障信息 |
| information | complete、missing、questions、evidence |
| root_cause | confirmed、root_cause、evidence.logs/code、business_changes、questions |
| business_confirmation | choice、selectedChangeIds、comment、user_id、root_cause_hash |
| prd | content、converged、questions、hash |
| prd_reviews | 独立审查数组；报告绑定 prd_hash，包含 converged、questions 等 |
| prd_feedback | 用户答复、答复人和对应 revision |
| ready_for_implementation | 同版 PRD 两次收敛判断均通过后的执行许可 |

business_changes 是一至三项具有唯一稳定 id 和 description 的关键业务行为。用户确认绑定根因哈希；独立审查绑定 PRD 内容 SHA-256。范围或 PRD 变化后旧确认与审查不能继续授权执行。

## 3. 信息输入与源工单约束

input 的字符串字段为 mobi、environment、reproduction、steps、expected、actual、traceId、occurredAt、notes；triggeredOn74 为布尔值。reproduction 为 always、intermittent 或 unknown。

mobi 必须匹配源工单正文或评论中的 mobi:xxxx 标记。必现问题需要明确 mobi、环境、步骤、预期和实际行为；偶现问题还要求 triggeredOn74=true，且 traceId 必须与源工单中的 trace-id 标记一致。仅在本地补充 traceId 不能替代工单证据。规则见 [05-信息诊断 Agent 规则](05-信息诊断agent-规则.md)。

补充信息创建新的独立快照并重置信息诊断，清除下游根因、业务确认、PRD 和审查许可。重新读取工单调用飞书适配器保存新源版本，再从信息诊断开始；重试复用已有源及补充输入，但重新校验全部门槛，不直接恢复实施。

## 4. 产物与读取接口

执行目录为 /data/attempts/{job_id}/{attempt_id}，挂载为 Runner 内 /workspace。snapshot.json 独立保存快照；阶段报告写 stage-report.json 和 result.json。只有已通过根因、业务确认和 PRD 双审的实施阶段，才将经过确认的 PRD 写入 .trellis/tasks/bugfix/prd.md。

GET /api/jobs/{id}/artifacts/{name} 返回 JSON 对象，包含 name、snapshotVersion、revision、data；name 限定 snapshot、information、root-cause、prd、prd-reviews。产物未生成返回 404，接口不是任意文件下载或服务器路径浏览。

来源：[产物与交互 API](../../backend/app/workflow_api.py)、[上下文装配](../../backend/app/trellis_context.py)。

## 5. HTTP 接口与前端动作

除登录外均检查本地 session；共享工作区允许已登录成员查看任务。信息修改、源刷新、业务确认、PRD 答复仅允许有效发起人，写入必须绑定 expectedRevision。版本冲突返回 409，未授权返回 403，不存在返回 404。

| 方法与路径 | 请求或用途 |
| --- | --- |
| POST /api/login；POST /api/logout；GET /api/me | 本地身份会话 |
| POST /api/bug-preview | 飞书预览及仓库推荐 |
| POST /api/jobs；GET /api/jobs；GET /api/jobs/{id} | 创建与共享查询 |
| POST /api/jobs/{id}/information | {expectedRevision,input:{...}}，提交补充信息 |
| POST /api/jobs/{id}/refresh-snapshot | {expectedRevision}，重新读取飞书源工单 |
| POST /api/jobs/{id}/business-confirmation | {expectedRevision,choice,selectedChangeIds,comment} |
| POST /api/jobs/{id}/prd-feedback | {expectedRevision,answer} |
| GET /api/jobs/{id}/artifacts/{name} | 读取版本绑定的结构化产物 |
| POST /api/jobs/{id}/retry | 发起人重试失败、取消、未复现或仅诊断任务 |
| POST /api/jobs/{id}/cancel | 取消可取消状态 |
| POST /api/jobs/{id}/approve | 非发起人审核当前冻结候选 |
| GET /api/jobs/{id}/events | SSE 任务事件 |

前端分开展示快照、信息诊断、根因证据、业务选择、PRD 和独立复核。确认、要求调整、拒绝是三个显式操作；不自动选择业务变更。PRD 答复后重新收敛，原独立审查失效。请求冲突时显示错误并刷新详情，未获得 API 成功结果不能展示为已批准。

## 6. 外部认证与受控能力

| 集成 | 身份与边界 |
| --- | --- |
| 飞书 MCP | 服务级 OAuth，device code 授权并刷新，OAuth 文件位于服务持久目录 |
| 飞书 Plugin | Plugin ID/Secret 换取 token，配合 user_key；与 MCP 权限路径分开 |
| GitHub | GITHUB_READ_TOKEN 用于代码准备，GITHUB_TOKEN 用于发布，使用 Basic，不在 URL 保存 token |
| SSH 74 | 由可信协调器调用固定主机和受控日志查询程序；私钥不进入 Agent |
| Pi | 从只读配置种子复制到临时目录；不继承 Worker 的 GitHub token |

日志适配器只连接 192.168.2.74，配置项为 DIAG_SSH_USER、DIAG_SSH_KEY_PATH、DIAG_SSH_KNOWN_HOSTS、DIAG_LOG_QUERY_PROGRAM。StrictHostKeyChecking=yes，BatchMode=yes，使用明确密钥与 known_hosts；远端查询程序为运维配置的绝对可执行路径，只接受经字符约束的 --trace 或 --mobi 参数。trace 优先；必现问题缺 trace 时可按 mobi 取证。缺配置或无日志不能确认根因。

日志输出限长并脱敏后传给根因 Agent。调用者不能提交任意 SSH 命令，Agent 不能根据工单内容自行构造 shell 查询。来源：[log_source.py](../../backend/app/log_source.py)。

Git 缓存按仓库和分支隔离，首次 depth 40，后续 fetch depth 40；GIT_HTTP_PROXY 只配置 Git 获取，不代表飞书、模型和交付接口共用出口。来源：[worker.py](../../backend/app/worker.py)。
