# 设计一致性验收

本文以可验证契约检查总体设计、Agent 流程与代码一致性。组件关系、工作流和执行协议分别维护，不混用一张图表达多个维度。

## 输入与来源

- 工单快照独立保存，历史来源版本不可覆盖；用户补充与工单来源分开。
- mobi 必须匹配工单中的 mobi:xxxx；不从 reportNo 等对象推断。
- 偶现问题必须已在 74 触发，trace-id 匹配工单来源，备注不能伪造来源。
- 信息不足或矛盾时，进入 needs_input，不克隆修改工作区、不生成 PRD。
- 重新读取工单和补充信息会使旧根因、用户确认及审查失效。

## 根因、业务确认与 PRD

- 根因依赖协调器采集的 74 日志和代码证据，无日志不凭模型猜测放行。
- 分析阶段检查仓库基线及工作区未变；可信 spec 索引进入阶段上下文。
- 用户确认绑定根因内容版本；拒绝即停止，修改返回根因与范围讨论。
- PRD 在根因明确和业务确认后生成，问题未解决不进入实施。
- 主 Agent 与独立 Subagent 对同一 PRD 哈希通过后才允许创建修改 worktree。
- 分析仓库集合与实际修改仓库集合分开；候选只能是获准仓库的非空子集。

## 生命周期与恢复

- 状态写入校验 epoch，用户决策校验 revision，过期执行与旧页面不能推进。
- 每个 Agent 阶段有时限；协议完成、产物校验和进程结束分别检查。
- 收尾和 stdin 关闭等待有界；准备期间持续续租。
- 取消在执行阶段被检查，网络准备期间最多受单条有界命令时限约束。
- 失败重试重新经过信息门槛，保留快照和历史事件，不沿用旧批准。

## 审核与发布

- 候选绑定代码树、目标分支、基线及有效 PRD。
- 发起人不能审核自己的候选，发布只由可信交付器执行。
- 远端目标分支移动后停止交付；多仓 PR 中途失败保留恢复记录。
- 任务测试通过、合成协议测试通过和真实业务验收分别报告，不相互替代。
