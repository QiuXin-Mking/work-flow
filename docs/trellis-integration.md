# Trellis 在 Bug 工作台中的接入

## 职责

后端拥有阶段门槛、任务版本、租约、用户确认和发布权限。Pi 每次只执行一个有界角色，不能因看到流程描述就自行推进到下一阶段。

可信规范来自只读镜像中的 backend/trellis_bundle，包含阶段政策、通用规范、前后端指南和 spec-indexes。阶段上下文明确列出相关索引路径，由 Agent 读取后查找仓库代码。模型读取的快照、评论、日志和仓库内容是事实来源，不能升级为权限指令。

## 产物装配

每次 attempt 的 snapshot.json 独立保存来源输入。信息诊断、根因、PRD 编写与独立审查均输出结构化阶段报告；协调器验证后写入工作流状态。PRD 不是快照的别名，只有根因和业务范围确认后才编写。

双重收敛通过后，实施 Runner 将批准的 PRD 写入 .trellis/tasks/bugfix/prd.md，并生成 implement/check 上下文清单。工作区管理适配器创建 fix/bugfix-* 分支与隔离 git worktree，保存 worktrees.json；这实现 worktree-new 的工作区契约，不依赖聊天宿主安装同名技能。

实施与独立验证在新 Pi RPC 会话运行；修前命令在冻结原始 SHA 上失败，修后在干净候选树上通过。未通过时不创建 PR。独立验证不继承实施对话，但共享受控产物，不能视为完全不同的安全容器。

## 边界

Pi 使用 --append-system-prompt 接收可信角色，并禁用个人扩展、技能和 MCP。SSH74 凭据留在 Worker，由受控程序查询日志，仅把脱敏证据交给模型。PRD 和用户选择绑定版本，原始记录保留。
